- **cycle_queue / cycle_scale 的更新机制**（核对代码 + checkpoint 实测）：
  - 参数分组（exp:69-88）：三组只按参数名匹配 `'temporal_query'/'tq_gate'/'cpq'` 与 `'_proj'`；**cycle_queue、cycle_scale 都不匹配 → 落入 other_params，用基础 lr**，不属于 TQ 高 lr（×5）组。
  - 优化器：`optim.Adam`，**无 weight_decay**；`--cos 1 --tmax 10` → CosineAnnealingLR 是**周期 10 epoch** 的循环（100 epoch 内跑 10 个周期，不是单次长衰减），η_min=1e-8，每 epoch step 一次。
  - **梯度只来自 task_loss**：output_loss 比较 outputs_time vs outputs_text，而两分支加的是同一个 `cycle_scale*Q`（CALF.py:320-321 / 330-331）→ 差值里精确抵消 → 对 Q 与 s 的梯度恒为 0；feature_loss 取的是加先验之前的 GPT-2 中间层 → 也够不到。
  - **乘法门的冷启动耦合**：Q 初始全 0、s 初始 0.1。∂L/∂s = Σ grad·Q ≡ 0 → **s 一开始完全被锁死**；∂L/∂Q ∝ s = 0.1 → Q 以 1/10 速率慢启动。必须先有 Q 非零，s 才解锁。
  - **非 Solar 数据集**：`future_cycle_index=None` → 先验整段跳过 → Q 与 s 梯度恒 0，**永远停在初始值（Q=0、s=0.1）**，是死参数。
  - 加载顺序：checkpoint 在 `Exp_Basic.__init__`（exp_basic.py:13-38，strict=False）加载，**早于** train() 里的 `_select_optimizer()`；CALF 重写 `load_state_dict`（CALF.py:511-533）只对**传入的 state_dict** 做列切片，模块内 Parameter 张量身份不变 → 优化器分组始终有效。`freeze_backbone` 只冻结名字含 'gpt2' 的，cycle_queue 不受影响。

- **`models/GPT2_arch.py` 讲解 + 实测（并更正旧结论）**：文件 221 行，只定义 `AccustumGPT2Model(GPT2Model)`，作用有三：
  1. `__init__` 里 `for block in self.h: attn.bias.fill_(True)`（第 15-18 行）——把 causal mask 的 bool 下三角 buffer 全填 True。该 buffer 在 transformers 4.30.1 中是 `torch.tril(torch.ones(...,dtype=torch.bool))`、`persistent=False`，`_attn` 里 `torch.where(causal_mask, attn_weights, mask_value)` 因此不再屏蔽任何位置 → **token（站点）维双向注意力**。实测（`D:\software\conda\envs\calf`）：只改最后一个 token 的嵌入，第一个 token 输出差异 = **1.291**（全 True）vs **0.0 恰好为零**（手动还原下三角）。`h.0.attn.bias` **不在 state_dict 里**（persistent=False），所以 `from_pretrained` 不会覆盖这个改动。
  2. `accustum_forward` 是 HF 4.30.1 `GPT2Model.forward` 的逐行拷贝（第 20-211 行）——保留 `self.bias` 掩码逻辑，并显式产出 `hidden_states` / `attentions`。在 4.30.1 下直接 `super().forward` 也能生效，这段拷贝是冗余但无害的维护负担。
  3. `forward`（第 213-215 行）覆盖父类，返回 **二元组** `(last_hidden_state, hidden_states)`，而非 `BaseModelOutputWithPastAndCrossAttentions` —— 这正是 `cmLoss` 逐层对齐（`intermidiate_feat_time[::-1]`）需要的形式。
