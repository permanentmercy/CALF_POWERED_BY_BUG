# 三损失权重完全解耦与独立超参控制规划 (Subplan v2.6)

本文档依照团队规范维护，定义 CALF 批量实验控制面板与配置管理核心中关于**“三个损失权重（task_w, feature_w, output_w）彻底解除自动求和为1的约束，全面实现独立自主配置与循环网格扫描”**的技术改造方案。

---

## 一、需求背景与目标

1. **用户核心指令**：
   - 用户明确要求：“把三个loss改成不自动求和成1，独立开来”。
2. **历史耦合逻辑剖析**：
   - 此前为了快速执行单纯的单形约束实验（Simplex constraint），在 `config_manager.py` 的任务生成阶段，代码强制执行了 `output_w = 1.0 - task_w - feature_w` 的动态覆盖；
   - 一旦用户指定了非求和为 1 的组合（例如 `task_w=1.0, feature_w=0.1, output_w=0.5`），或者 `1.0 - task_w - feature_w <= 0`，任务生成器就会将 `output_w` 篡改或直接抛弃跳过该任务；
   - 在 GUI 界面中，存在自动联动计算按钮及强制提示 `[三损失和: ... = 1.000]`，给用户造成无法独立调节三者的限制。
3. **改造目标**：
   - **完全独立自主**：`task_w`（时序任务权重）、`feature_w`（特征对齐权重）、`output_w`（输出对齐权重）三者完全作为独立超参数；
   - **解除求和为1约束**：三者之和可为任意正数、零甚至消融负数，不再被系统强制求和为 1，也不再因 `output_w <= 0` 而被跳过；
   - **全自由度循环扫描**：支持在循环参数（Loop Parameters）中分别或同时对 `task_w`、`feature_w`、`output_w` 进行网格扫描（例如 `output_w: [0.0, 0.2, 0.5, 1.0]`）；
   - **界面交互清晰呈现**：去除强制求和联动按钮，更新界面提示文案，明确标示三参数均为完全独立设定。

---

## 二、架构改动与实施方案

### 1. 配置管理器核心解耦 (`scripts/batch_runner/config_manager.py`)
- 移除 `generate_task_combos` 中默认将 `output_w` 覆写为 `1.0 - task_w - feature_w` 的逻辑；
- 移除 `if float(output_w) <= 0: continue` 的强制跳过过滤；
- 保留三者各自独立的数据解析流程：优先取自 `loop_dict`，缺省取自 `fixed_params`；
- （向下兼容）：仅当配置中显式写入字符串 `"auto"` 时才执行 `1.0 - tw - fw` 计算，其余情况严格保留用户设定的独立数值。

### 2. GUI 图形控制面板优化 (`scripts/batch_runner/gui_panel.py`)
- 移除优化器分组下的联动计算按钮 `⚡ 根据 task_w 和 feature_w 自动联动 output_w` 及求和标签；
- 替换为直观的蓝色独立提示标签：`💡 [提示] task_w、feature_w、output_w 三个损失权重完全独立设置，不自动求和为1，支持各自独立设定与循环网格扫描。`；
- 在添加/编辑循环超参对话框的推荐参数列表中加入 `output_w`。

---

## 三、验收标准

1. 用户在固定参数中设置任意 `task_w`, `feature_w`, `output_w`（和不等于 1），任务生成列表严格按设定参数生成，不被篡改。
2. 在循环参数中加入 `output_w` 列表或范围（如 `0:0.5:1.0`），生成包含 `output_w` 维度的正交笛卡尔积组合。
3. `output_w` 为 0 时任务正常生成并执行，不被误判为无效组合。
4. GUI 面板启动与模板载入零异常。
